3 · Write yours

Three steps, one notebook

bench/plugin_template.ipynb has a working example of all five sockets, with the inputs and outputs explained above each cell. Copy it and delete what you don't need.

Copy the template

# your own notebook: no merge conflicts
cd bench
cp plugin_template.ipynb carla.ipynb

Register under your name

# the first cell already loads the engine
@register("qaoa", "carla_ws")
def warm_start_circuit(J, p=1):
    ...
    return qc, theta, scale

Prefix names with your name: a second "ws" would silently replace the first.

Run it

if not PLUGINS_ONLY:  # skip on merge day
    cfg = Config(qaoa="carla_ws", ps=(1, 2))
    rows = run_bench(["toy", 8, 10], 3, cfg)
    display(summarize(pd.DataFrame(rows)))

About 1–2 minutes on a laptop. Random guessing, local search and annealing race next to yours; the template's section 7 adds the baseline QAOA on the same puzzles.

4 · Fair play

Four ways to win by accident

Each one makes a method look better without it being better. The bench handles the bookkeeping if you follow these.

ATraining shots count

A trainer that runs the circuit 30 times × 256 shots has used 7,680 shots before the real run starts. tts99 includes them.

closed-form p=1
560
COBYLA p=1
train 7,680
8,240

Illustrative numbers. Pink = training shots, blue = sampling.

BOne row per shot

Success rate = optimal rows ÷ all rows. Dropping bad rows makes it look higher, even though no extra answers were found.

keep 2,048 rows
1,748 not optimal
15%
drop to 400 rows
300 optimal
75% ✗

Fix a shot instead of dropping it, and return the costs you evaluated as extra_evals.

CNew evidence, new "best answer"

Changing how votes are weighted changes which answer scores best. Finding that answer more often says nothing about finding the real haplotype.

✗ P_budget"did we hit the best answer of this scoring?"
✓ switch_err"how many phase switches away from the hidden truth?"

DSame puzzles, same budget

The bench gives every method the same seeds, puzzles and shot budget (2,048 by default), and always runs random guessing as the floor.

✓ one run_bench callall methods side by side in one table
✗ different settingsanother seed or gen means other puzzles: numbers can't be compared
5 · Shared conventions

Six things everyone agrees on

All match the baseline notebook, so its code can move into a plug-in unchanged.

bit order
x[0] = SNP 1

Arrays and bitstrings list SNP 1 first.

reads
0 · 1 · −1

−1 means the read has no letter at that SNP.

votes
A, D (i < j)

Same / opposite counts, upper triangle only.

Ising
J = (D − A) / 2

offset = sum(A + D) / 2, z = 1 − 2x.

angles
[γ₁…γₚ, β₁…βₚ]

All gammas first, then all betas.

cost layer
RZZ(2γ·J / scale)

No measurements in the circuit; the backend adds them.

8 · Merge day

From four notebooks to one result

  1. each of usOwn branch, own notebookuser/<name> touches only bench/<name>.ipynb.
  2. each of usSmoke testrun_bench(["toy", 8, 10], 1, cfg) runs in seconds without a fail column.
  3. togetherMerge to mainSeparate notebooks, so no conflicts. qgd_bench.ipynb opened on its own still passes its 8 checks.
  4. TudorRun the gridThe 5 rows above, same seeds. Big N on Kaggle with the plug-in notebooks bundled in.
  5. togetherOne plot per questionEach owner reads their row against the baseline and writes the conclusion or limitation.
